# QQ 群状态监控

这个插件通过 OneBot WebSocket 监听 QQ 群消息，用来帮开发者盯住群里的求助、疑问句、压缩包文件，以及有人 @ 授权 QQ 的情况。

它不会启动或安装 QQ 客户端，只负责连接已经运行的 OneBot 服务。需要本地先准备 NapCat 或其他兼容 OneBot 的实现。

## 下载与准备

推荐使用 NapCat：

```text
https://github.com/NapNeko/NapCatQQ/releases
```

建议下载 `NapCat.Shell.zip`。如果你已经使用隔壁的 QQ 自动回复插件，并且它旁边存在 `NapCat.Shell` 目录，本插件会在面板里显示“已检测到”。检测到只表示本地目录存在，最终是否可用仍以 OneBot 是否连接为准。

## NapCat 网络配置

1. 启动 NapCat 并登录 QQ。
2. 打开 NapCat WebUI。
3. 在左侧进入“网络配置”。
4. 新增 WebSocket 服务端，地址通常监听在 `ws://127.0.0.1:3001`。
5. 如果设置了 Token，把同一个 Token 填到本插件面板。
6. 保存 NapCat 配置后，回到本插件点击“启动监听”。

## 插件配置

在插件面板中依次填写：

- `OneBot WebSocket`：默认 `ws://127.0.0.1:3001`。
- `访问令牌`：NapCat 网络配置里设置了 Token 才需要填。
- `监控群号/名称`：每行一个群号，也可以写成 `1234567｜一群` 或 `1234567|一群`。留空表示监听所有收到的群消息。
- `授权 QQ`：有人在群里 @ 这些 QQ 时，插件会把猫娘语气回复发回 QQ 群，并且不会再进入疑问句或压缩包提醒规则。
- `相关负责人`：每行一个，格式为 `QQ|名称`。为了避免打扰太多人，触发问题或压缩包规则时会从已配置负责人里随机 @ 一位。
- `问题转移模式`：开启后选择目标类型，并填写目标 QQ/群号。插件不会在原群聊天、弹窗或 @ 负责人，只会把疑问关键词命中的消息发送到目标群聊或好友；目标为群聊时不要填当前来源群。目标也可以直接写成 `好友:123456`、`用户:123456` 或 `群聊:123456` 来强制类型。
- `表情包库`：直接选择 PNG、JPG、GIF、WebP 文件导入，文件名会作为表情包名称。猫娘会根据这些名称判断要不要在回复后单独发一条表情包。
- `旧版表情包规则`：可选兼容项，每行一个，格式为 `名称|图片URL或本地路径|关键词1,关键词2|触发原因|概率`。

示例：

```text
1234567｜一群
7654321｜测试群
```

负责人示例：

```text
123456789|后端同学
987654321|前端同学
```

负责人配置仍兼容旧的 `QQ|名称|关键词` 写法，但当前版本不会按关键词筛选负责人。

导入表情包后，猫娘只会知道表情包名称，不会读取图片内容。建议把文件名起成容易判断的名字，例如 `开心.gif`、`疑惑.png`、`收到.webp`。

旧版表情包规则示例：

```text
思考|https://example.com/stickers/think.png|怎么,为什么,请问|question|1
安慰|file:///D:/Neko/stickers/pat.png|报错,崩溃,无法,闪退|question|0.8
压缩包|/Users/me/Neko/stickers/file.gif|zip,rar,7z,日志|archive_file|1
```

说明：

- 导入的表情包会保存在插件数据目录，发送时会作为单独的 OneBot `image` 消息发送。
- 旧版规则里的 `图片URL或本地路径` 会作为 OneBot `image` 消息段里的 `file` 发送给 NapCat。
- URL、本地绝对路径、`file:///` 路径是否可用，取决于你当前 NapCat/OneBot 实现。
- `触发原因` 可填 `question`、`archive_file`，多个用逗号分隔。
- `概率` 是 `0 ~ 1` 小数，留空等同于 `1`。
- GIF 可以作为表情包导入；本插件会按图片消息段发送，实际是否动图播放取决于 NapCat 和 QQ 客户端对该 GIF 的处理。

## 触发行为

- 问题转移模式：开启后原群保持安静，其他不会生效的选项会在面板里变灰；配置目标群聊后，疑问关键词命中的消息会以合并转发卡片发送到目标群；配置目标好友后，会以普通私聊文本发送，避免部分 OneBot 环境的好友合并转发 110 失败。来源会显示监控群自定义名称，消息 ID 不会展示，改为展示时间戳；短时间重复内容会按提醒冷却秒数合并。
- @ 授权 QQ：最高优先级，只走日常聊天线；即使消息里有疑问词或压缩包，也不会进入提醒规则线。
- 图片/视频：整条消息不会进入提醒规则线，不会 @ 负责人；没有 @ 授权 QQ 时也不会触发日常聊天回复。
- 疑问句：未 @ 授权 QQ、且不是图片/视频消息时，只有“怎么 / 为什么 / 无法 / 报错”等疑问关键词会提醒；`?`、`？` 本身不会触发提醒。
- 压缩包文件：未 @ 授权 QQ 时，收到 `.zip`、`.rar`、`.7z`、`.tar.gz` 等文件会提醒，并可 @ 配置好的相关负责人。
- 负责人协助：有问题或压缩包命中时，插件会在群里随机 @ 一位配置好的相关负责人。
- 表情包：猫娘先发送文字回复；如果模型选择了某个导入表情包，会再单独发送一条图片消息。不会把文字和表情包塞进同一个 QQ 消息框。

## 面板检测项

面板会检测：

- 本地是否存在隔壁 QQ 插件旁边的 `NapCat.Shell` 目录。
- OneBot 地址是否是 `ws://` 或 `wss://`。
- 当前是否已连接 OneBot。
- 是否配置授权 QQ。
- 是否配置相关负责人。
- 监控范围是指定群，还是所有群。
- 是否配置表情包库或旧版表情包规则。

## 常见问题

### 启动监听失败

检查 NapCat 是否正在运行，WebSocket 服务端是否启用，端口和 Token 是否一致。

### 检测到 NapCat.Shell 但 OneBot 未连接

目录存在不代表服务已启动。请先启动 NapCat 并确认网络配置里的 WebSocket 服务端已启用。

### 没有弹窗提醒

检查“弹窗提醒”开关是否开启；如果短时间内重复触发，可能被提醒冷却时间合并了。

### 没有 @ 负责人

检查“有问题时 @ 负责人”开关是否开启，并确认负责人配置里有合法 QQ 号。

### 没有发表情包

检查“自动配表情包”开关是否开启，规则里的图片地址是否能被 NapCat 读取。可以先用网络图片 URL 测试，确认 OneBot 图片段可用后再换成本地路径。
